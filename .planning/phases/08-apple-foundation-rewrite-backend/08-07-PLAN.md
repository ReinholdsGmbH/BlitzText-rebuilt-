<objective>
CR-02 Fix: applyAutoFallbackIfNeeded greift beim Erst-Bootstrap nicht — Privacy-Invariante bricht.

Purpose: `refreshFoundationAvailability()` ruft `applyAutoFallbackIfNeeded()` aktuell nur bei State-Wechsel (`if new != foundationAvailability`). Initial-Wert ist hardcoded `.unavailable(.modelNotReady)`. Wenn `currentAvailability()` beim Cold-Boot ebenfalls `.unavailable(.modelNotReady)` liefert (häufiger Fall: erstes Modell-Loading nach Apple-Intelligence-Aktivierung), feuert der Inequality-Check nicht, und der Auto-Fallback-Pfad wird nie betreten — obwohl alle anderen Bedingungen (API-Key + .appleFoundation-Backend) erfüllt sind. User landet im Limbo: alle Rewrite-Calls werfen `AppleFoundationError.unavailable`, obwohl AC-AVAIL-1 + ROADMAP-SC 4 eigentlich Auto-Fallback fordern.

Output: Unconditional Aufruf von applyAutoFallbackIfNeeded; Reset von didAutoFallbackToOpenAI bei .available; Regression-Test der Cold-Boot-Pfad pinnt.
</objective>

@Published var foundationAvailability: FoundationAvailability = .unavailable(.modelNotReady)  // hardcoded initial
@Published var didAutoFallbackToOpenAI: Bool = false

func refreshFoundationAvailability() {
    let new = availabilityProvider.currentAvailability()
    if new != foundationAvailability {  // ← state-equality-Guard verhindert Cold-Boot-Trigger
        foundationAvailability = new
        applyAutoFallbackIfNeeded()

}

private func applyAutoFallbackIfNeeded() {
    guard !didAutoFallbackToOpenAI else { return }                                       // Self-Idempotency
    guard foundationAvailability != .available, !apiKey.isEmpty else { return }

    if switched {
        rewriteBackendForPlus = .openAI
        rewriteBackendForRant = .openAI
        didAutoFallbackToOpenAI = true
    }
}
