## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking issue] AppDelegate.enforceSingleInstance terminierte den Test-Host**
- **Found during:** Task 5 (initialer `xcodebuild test`-Run)
- **Issue:** Der hosted Test-Runner laedt die echte `BlitzText.app` als Bundle-Loader. Wenn der Entwickler die App nebenbei laufen hat, erkennt `applicationWillFinishLaunching` eine Doppel-Instanz, zeigt einen Modal-Dialog und ruft `exit(0)` — der Test-Host stirbt vor `establishing connection`. Fehler war: *"BlitzText encountered an error (Early unexpected exit, operation never finished bootstrapping... The test runner exited with code 0 before establishing connection.)"*
- **Fix:** `enforceSingleInstance()` early-returnt, wenn `ProcessInfo.processInfo.environment["XCTestConfigurationFilePath"]` gesetzt ist. Production behaelt die Doppel-Instanz-Pruefung 1:1.
- **Files modified:** `BlitzText/App/AppDelegate.swift`
- **Commit:** `4f28c47`

**2. [Plan-konform] ModeProcessor.recorder bleibt konkret**
- **Issue:** Die Plan-Verify-Regex hat `recorder: RecorderProtocol? = nil` als sichtbares Zeichen erwartet. Das ist im neuen Init genau so umgesetzt — zusaetzlich bleibt `let recorder = AudioRecorder()` als public-readonly Property erhalten, weil `RecordingHUDController(recorder: modeProcessor.recorder, …)` den konkreten Recorder fuer `currentLevel`-Beobachtung braucht. Die Pipeline (`start()`/`stop()`) nutzt jetzt `activeRecorder` (= injizierter Fake oder `recorder`-Default).
- Diese Doppelstruktur ist im RESEARCH.md Pattern-3-Spielraum und wurde nicht als Deviation, sondern als gewollter Design-Trade-off umgesetzt.

## Anti-Flake Compliance

- Kein `AVAudioEngine`-Aufruf in den Tests (FakeAudioRecorder ist reines Wert-Objekt).
- Kein Netzwerk (kein `URLSession`-Aufruf in den Doubles oder im SmokeTest).
- Kein Keychain-Schreibzugriff (SettingsStore wird in den SmokeTests nicht instanziiert).
- Kein TCC-Prompt (kein `CGEventTap`-Pfad in den Tests; `enforceSingleInstance` skippt im Hosted-Run).

## Open Items / Notes for Following Plans

- **`HistoryStore` Pfad-Injection (T-02-02 accept):** SmokeTests beruehren keinen HistoryStore. Pipeline-Tests in 02-02 / 02-03 muessen den `~/Library/Application Support/BlitzText/history.json`-Pfad scopen oder das History-Append in den Tests vermeiden — sonst wird die echte User-History angefasst. Empfehlung fuer 02-02: ModeProcessor-Tests instanziieren ihn ohne Aufruf von `runPipeline.deliver+history.append`, oder `HistoryStore` bekommt einen optionalen `directoryURL`-Parameter (Phase-4-Refactor).
- **`SettingsStore.migrateAPIKeyFromUserDefaultsIfNeeded()` (T-02-01 accept):** Nicht von SmokeTests beruehrt. Falls ein spaeterer Plan SettingsStore in einem Test instanziiert, sollte er entweder den Migrations-Pfad meiden oder das Keychain-Service-Tag pro Test isolieren.
- **`HotkeyManager`-State zwischen Tests:** `decideTransition` mutiert `currentMode`/`lastTriggerAt` auf der Instanz — Tests muessen pro Szenario eine frische `HotkeyManager`-Instanz erzeugen (oder einen Reset-Helper bauen). Fuer 02-02 (Hotkey-State-Machine-Tests) ist das die zentrale Konvention.
