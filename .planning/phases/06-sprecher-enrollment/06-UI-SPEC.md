## Spacing Scale

Das Projekt nutzt durchgehend SettingsView-Muster: `spacing: 20` zwischen Sections,
`spacing: 8` innerhalb von Sections, `padding: 10` auf Cards/Rows, `.padding(24)` auf dem
ScrollView-Inhalt. Für das Enrollment-Sheet gelten dieselben Abstände.

| Token | Wert | Verwendung |
|-------|------|------------|
| xs | 4px | Icon-zu-Text-Gap, Badge-Innenabstand |
| sm | 8px | Spacing innerhalb einer Section / Card-Padding |
| md | 16px | Standardabstand zwischen verwandten Elementen |
| lg | 20px | Section-zu-Section-Spacing |
| xl | 24px | Sheet-Rand-Padding (`.padding(24)`, analog SettingsView ScrollView) |
| 2xl | 32px | Vertikal-Spacing zwischen Haupt-Bereichen im Sheet |

Quelle: SettingsView.swift — `VStack(alignment: .leading, spacing: 18)` (Originalwert 18px, im
Sheet auf Token `lg = 20px` normiert), `.padding(20)` (im Sheet auf Token `xl = 24px` normiert),
`SpeakerRow: .padding(8)`, `LocalModelRow: .padding(10)`.

Ausnahme: Touch-Targets für Buttons sind ≥ 44 pt Höhe (macOS HIG). Kein extra Token nötig,
SwiftUI-Buttons erfüllen das von Natur aus bei `.bordered`/`.borderedProminent`.

## Typography

Das Projekt nutzt ausschließlich `.system`-Größen über SwiftUI-Textmodifikatoren.
Folgende 4 Größen sind im Enrollment-Sheet zulässig:

| Rolle | SwiftUI-Modifikator | Verwendung im Sheet |
|-------|---------------------|---------------------|
| Heading | `.title3` | Sheet-Titel "Sprecher-Profil aufnehmen" |
| Body | `.body` (Default) | Name-TextField-Label |
| Subheadline | `.subheadline` | Zustandstext ("Aufnahme läuft …", "Verarbeite …") |
| Caption | `.caption` | Restzeit-Anzeige, Qualitäts-Feedback-Caption, Fehler-Caption (rot) |

Gewichte: standard (400) + bold/semibold wo Kontrast nötig.
Body-Line-Height: SwiftUI-Standard (≈ 1.5 implizit).
Heading-Line-Height: SwiftUI-Standard (≈ 1.2 implizit).

Maximale Anzahl Font-Größen: 4 (title3, body, subheadline, caption). `.caption2` und `.headline`
werden im Enrollment-Sheet nicht verwendet.

Quelle: SettingsView.swift, DiarizerStatusBlock, SpeakerRow — konsistent `.caption`,
`.subheadline`, `.headline` ohne px-Fixwerte. `.headline` entfällt im Sheet zugunsten `.title3`.

## Color

Das Projekt nutzt kein eigenes Palette-System sondern ausschließlich semantische SwiftUI-Colors
und SF-Symbole-Farben. Folgendes ist in der bestehenden Codebasis etabliert:

| Rolle | SwiftUI-Color | Verwendung |
|-------|--------------|------------|
| Dominant (60%) | `.background` / `.windowBackground` | Sheet-Hintergrund, ScrollView |
| Secondary (30%) | `.quaternary` | Row-Cards (`.background(.quaternary, in: RoundedRectangle)`) |
| Akzent (10%) | `.accentColor` (blau) | "Aufnahme starten"-Button (`.borderedProminent`), aktiver Fokus-Ring |
| Fehler / Destruktiv | `.red` | Fehler-Caption, Fehler-Symbol (`exclamationmark.triangle.fill`) |
| Warnung | `.orange` | Diarizer-nicht-installiert-Banner (analog SprecherTab-Muster) |
| Erfolg | `.green` | Bestätigungssymbol nach Enrollment, "PERMANENT"-Badge |

Akzent reserviert für: "Aufnahme starten"-Button (primäre CTA im Sheet), aktive Pegel-Balken-Farbe
während Aufnahme.

Rot reserviert für: Fehler-Caption unter Pegel, Fehler-Icon, keine anderen Elemente.

Orange reserviert für: Disabled-Banner wenn Diarizer nicht installiert (genau wie bestehende
SprecherTab-Warning-Row).

Primärer visueller Anker: "Aufnahme starten"-Button in `.borderedProminent` (Akzent-Blau) zieht
das Auge als einziges farbiges Element im Sheet.

## Surfaces & Layout

### Surface 1: SprecherTab — Enrollment-Einstieg (bestehende View, Erweiterung)

Position im Tab: Unterhalb der `allSpeakersSection`, oberhalb von `thresholdSection`, als neue
eigene Section `enrollmentSection`.

```
┌────────────────────────────────────────────────┐
│  ENROLLMENT                          [caption]  │
│  [Button "Neues Profil aufnehmen"]              │  ← .borderedProminent wenn aktiv
│  [Disabled-Caption — nur wenn !isInstalled]     │  ← .caption, .secondary
└────────────────────────────────────────────────┘
```

**Button-Zustände:**

| Zustand | Visuell | Interaktion |
|---------|---------|-------------|
| Diarizer installiert | `.borderedProminent` (Akzent-Blau) | Öffnet Sheet |
| Diarizer nicht installiert | `.disabled(true)`, ausgegraut | Kein Tap-Effekt |
| Diarizer installiert, aber Recorder aktiv (Diktat läuft) | `.disabled(true)` | Kein Tap (AVAudioEngine-Konflikt) |

**Disabled-Caption** (nur sichtbar wenn `!diarizerManager.isInstalled`):

> "Diarizer-Modell nicht installiert. Aktiviere Sprechererkennung im Backend-Tab."

Stil: `.font(.caption).foregroundStyle(.secondary)` — analog bestehende Captions in LokalTab.

## Komponentenspezifikationen

### Komponente A: Pegel-Visualisierung (LevelMeterBar)

Datenquelle: `AudioRecorder.currentLevel: Float` (0.0 – 1.0, logarithmisch skaliert, @Published).

Darstellung: Horizontaler Balken, volle Breite des Sheet-Inhalts.

```swift
// Visuelles Muster (analog RecordingHUDView-Pegel)
GeometryReader { geo in
    ZStack(alignment: .leading) {
        RoundedRectangle(cornerRadius: 4)
            .fill(.quaternary)
            .frame(height: 8)
        RoundedRectangle(cornerRadius: 4)
            .fill(Color.accentColor)
            .frame(width: geo.size.width * CGFloat(viewModel.currentLevel), height: 8)
    }
}
.frame(height: 8)
.animation(.linear(duration: 0.05), value: viewModel.currentLevel)
```

| Eigenschaft | Wert |
|-------------|------|
| Höhe | 8 pt |
| Eckradius | 4 pt |
| Hintergrundfarbe | `.quaternary` |
| Füllfarbe aktiv | `.accentColor` (Blau) |
| Füllfarbe Stille | `.quaternary` (kein Ausschlag) |
| Animation | `.linear(duration: 0.05)` — flüssig, kein Overshoot |
| Sichtbarkeit | Nur in State `.recording(...)` |

### Komponente B: Restzeit-Anzeige

Datenquelle: `EnrollmentViewModel.state.remainingSeconds` via `if case .recording(let s) = state`.

```swift
Text("\(remainingSeconds) s verbleibend")
    .font(.caption)
    .foregroundStyle(.secondary)
    .monospacedDigit()  // kein Layout-Sprung bei 15 → 9
```

| Eigenschaft | Wert |
|-------------|------|
| Font | `.caption` |
| Farbe | `.secondary` |
| Digit-Stil | `.monospacedDigit()` — verhindert Layout-Verschiebung |
| Sichtbarkeit | Nur in State `.recording(...)` |

Countdown-Fortschritt: Kein Ring/Kreis nötig. Text reicht (15 s ist kurz, keine lange Wartezeit).

### Komponente C: Verarbeitungs-Indikator

```swift
HStack(spacing: 8) {
    ProgressView().controlSize(.small)
    Text("Profil wird erstellt …")
        .font(.subheadline).foregroundStyle(.secondary)
}
```

Sichtbarkeit: Nur in State `.processing`.

### Komponente D: Fehler-Caption

```swift
HStack(spacing: 6) {
    Image(systemName: "exclamationmark.triangle.fill")
        .foregroundStyle(.red)
    Text(errorMessage)
        .font(.caption)
        .foregroundStyle(.red)
}
```

Sichtbarkeit: Nur in State `.failed(let message)`.
Verhalten nach Fehler: Caption bleibt sichtbar, Name-Feld behält vorherige Eingabe, Buttons
stehen für erneuten Versuch bereit. Sheet schließt sich NICHT automatisch.

### Komponente E: Aufnahme starten / Stopp Button

| Zustand | Button-Label | Stil | Disabled? |
|---------|-------------|------|-----------|
| `.idle`, Name leer | "Aufnahme starten" | `.borderedProminent` | `true` |
| `.idle`, Name ausgefüllt | "Aufnahme starten" | `.borderedProminent` | `false` |
| `.recording(...)` | "Stopp" | `.bordered` | `false` |
| `.processing` | "Stopp" | `.bordered` | `true` (deaktiviert während Verarbeitung) |
| `.done` | — | — | Sheet bereits geschlossen |
| `.failed(...)` | "Aufnahme starten" | `.borderedProminent` | `false` (erneuter Versuch) |

"Enrollment abbrechen"-Button (trailing-aligned links): immer sichtbar, `.plain`-Stil oder
sekundäres `.bordered`, schließt Sheet wenn State != `.processing`. Während `.processing` disabled.

## Zustandsübergänge

```
.idle
  │  User tippt Name + klickt "Aufnahme starten"
  ▼
.recording(remainingSeconds: 15)
  │  Countdown läuft (1 s Takt), Pegel animiert
  │  User klickt "Stopp" ODER Auto-Stopp nach 0 s
  ▼
.processing
  │  Spinner + "Profil wird erstellt …"
  │  enrollSpeaker async throws
  ├─► .done → Sheet dismiss (automatisch, 0.3 s Delay für visuelles Feedback)
  └─► .failed(message) → Fehler-Caption inline
```

Transition `.done → Sheet schließt`: kein extra Bestätigungs-Dialog. Sheet schließt automatisch.
Bestätigung erfolgt durch Erscheinen des neuen Profils in der `allSpeakersSection` darunter.

## Interaktionsverträge

### Vertrag 1: Button-Disabled-Logik (Name-Feld)

```
"Aufnahme starten"-Button ist .disabled(...) wenn:
  state != .idle
  ODER name.trimmingCharacters(in: .whitespacesAndNewlines).isEmpty
```

Kein Debounce nötig — SwiftUI `.onChange(of: name)` reicht.

### Vertrag 2: Auto-Dismiss nach .done

```swift
.onChange(of: viewModel.state) { newState in
    if case .done = newState {
        DispatchQueue.main.asyncAfter(deadline: .now() + 0.3) {
            showEnrollmentSheet = false
        }
    }
}
```

0.3 s Delay gibt dem User visuelles Feedback bevor das Sheet verschwindet. Kein Konfetti, kein
Toast nötig — das neue Profil erscheint direkt in der allSpeakersSection.

### Vertrag 3: Pegel-Binding

```swift
// EnrollmentSheet bindet direkt auf viewModel.currentLevel:
@Published private(set) var currentLevel: Float = 0

// Wird in EnrollmentViewModel via Combine aus recorder.$currentLevel gesetzt:
recorder.$currentLevel
    .receive(on: RunLoop.main)
    .assign(to: &$currentLevel)
```

### Vertrag 4: Countdown-Anzeige (kein Layout-Sprung)

`.monospacedDigit()` auf der Restzeit-Anzeige ist Pflicht. Ohne es springt das Layout bei
Übergang von zweistellig (15–10) auf einstellig (9–0).

### Vertrag 5: Gleichzeitige Diktat-Aufnahme verhindern

"Neues Profil aufnehmen"-Button im SprecherTab ist zusätzlich disabled wenn
`modeProcessor.state != .idle`. Caption optional (nicht zwingend — der User wird selten
gleichzeitig diktieren und Enrollment öffnen wollen).

Konkrete Prüfung im SprecherTab:
```swift
.disabled(!diarizerManager.isInstalled || modeProcessor.state != .idle)
```

## DSGVO-Hinweis (keine UI, aber Kontrakt-Marker)

Das Enrollment-Sheet persistiert kein Audio. Die temporäre WAV-Datei (`AudioRecorder.stop() → URL`)
wird nach `enrollSpeaker(audioURL:name:)` nicht aufbewahrt. Der Executor muss sicherstellen,
dass `FileManager.default.removeItem(at: audioURL)` nach Embedding-Extraktion aufgerufen wird
(oder der Temp-Pfad automatisch bereinigt wird). Kein UI-Element nötig — reiner Backend-Kontrakt.
